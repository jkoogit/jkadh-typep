# 12. JKADH 6대 하네스 라이프사이클 거버넌스 및 루프 표준 (Lifecycle Governance)

## 12.1 개요 및 프로세스 철학
JKADH AI 개발 플랫폼은 무분별한 소스코드 직접 수정(No-check Direct Write)을 원천 차단하고, 엄격한 품질 게이트와 작업 추적성을 보장하기 위해 **6대 표준 라이프사이클 단계(6-Stage Lifecycle Process)**를 필수 의무 규정으로 정의합니다.

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  #세션시작    │ ──> │  #태스크시작  │ ──> │  #태스크처리  │ ──> │  #태스크정리  │ ──> │  #태스크승급  │ ──> │  #세션정리    │
│ Session Init │     │ Task Init    │     │ Task Execute │     │ Task Wrap-up │     │ Promotion    │     │ Session Close│
└──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘     └──────────────┘
  - 계획/기획 검토     - 작업브랜치 생성     - 7-Phase 루프 실행    - PR 문서+원격발행   - dev➔stg➔main       - 세션명 한글현행화
  - 한글 세션명 초안   - 이슈 문서+원격발행  - 3대 시나리오 테스트  - 원격 dev 머지      - 미구현/보완 정리   - 회고록/백로그 갱신
  - DB 세션 레코드     - 태스크 DB 등록     - DB 물리적 변경 확인  - 작업자 소스 리뷰   - DB 태스크 완료 갱신 - 원격 승급 & 이슈종료
  - 태스크시작 P 작성  - 1턴 기획 논의      - 1턴 자체 보완        - 승급 프롬프트 작성 - 차기 태스크 P 표시 - 다음세션 P 작성
```

> **🚨 Gatekeeper 핵심 제약 원칙**:
> 1. `#세션시작` 시 정의하는 **세션명 초안은 브랜치명이 아닌 직관적인 "한글 세션명"**으로 정의합니다.
> 2. `#태스크시작` 시 생성하는 **작업 브랜치는 `task/{태스크명}` 접두사**를 준수하며, **로컬 문서(`/docs/issues/`) 작성 및 원격 레포지토리 이슈 등록**을 함께 완료하기 전에는 어떠한 소스 코드도 작성할 수 없습니다.
> 3. `#태스크정리` 시 **로컬 PR 문서(`/docs/pull_requests/`) 작성과 원격 레포지토리 PR 등록**을 수행하고 원격 `dev` 브랜치에 머지합니다.

## 12.2 6대 단계별 세부 공정 및 게이트키퍼 체크리스트

### 1️⃣ `#세션시작` (Session Initialization)
* **목적**: 작업계획 검토, 세션명 정의, DB 세션 레코드 생성 및 착수 준비.
* **실행 절차**:
  1. **작업계획 검토**: 2계층 작업그래프(DAG)의 선행 의존성 및 차기 목표 노드 상태 확인.
  2. **세션명 초안 정의 (한글 명명 규칙)**: 브랜치명이 아닌 명확한 목적이 드러나는 한글 세션명 정의 (예: `[세션] PostgreSQL 스키마 개별/그룹/전체 현행화 및 하네스 거버넌스 프로세스 수립`).
  3. **작업기획 논의**: 이번 세션에서 완결할 핵심 스코프와 리스크 범위 1턴 협의.
  4. **세션정보 추가 (DB)**: PostgreSQL `harness_sessions` 테이블에 세션 정보 INSERT (`status: 'IN_PROGRESS'`).
  5. **태스크시작 프롬프트 작성**: 1차 작업 노드 진입을 위한 `#태스크시작` 프롬프트 출력.
* **게이트 체크리스트**:
  - [ ] 한글 세션명 초안 정의 완료
  - [ ] DAG 선행 작업 완료 여부 확인
  - [ ] `harness_sessions` DB 등록 완료
  - [ ] `#태스크시작` 프롬프트 준비 완료

---

### 2️⃣ `#태스크시작` (Task Initialization)
* **목적**: 작업 브랜치 생성, 이슈 발행, 태스크 기획 논의 및 DB 상태 초기화.
* **실행 절차**:
  1. **작업 브랜치 생성**: `task/{태스크명}` 규격으로 브랜치 생성 (예: `task/db-granular-schema-migration`).
  2. **이슈 생성 (문서 + 원격 레포지토리)**:
     - 로컬 문서: `/docs/issues/{번호}-{태스크명}.md` 생성 (제목/내용 템플릿 준용).
     - 원격 레포: GitHub 저장소에 동일한 이슈 등록 및 이슈 번호(#) 발급.
  3. **태스크작업 기획 논의**: 3대 시나리오(필수 정상/오류 복구/예외 경계) 및 인터페이스 계약(Contract) 확정.
  4. **태스크정보 추가 (DB)**: `task_nodes` 상태를 `IN_PROGRESS`로 갱신하고 `task_execution_loops` 초기화.
* **게이트 체크리스트**:
  - [ ] `task/...` 작업 브랜치 생성 완료
  - [ ] 로컬 이슈 문서 작성 및 원격 레포 이슈 등록 완료
  - [ ] 3대 시나리오 기획 및 인터페이스 확정
  - [ ] `task_nodes` DB 상태 갱신 완료

---

### 3️⃣ `#태스크처리` (Task Execution & Loop Harness)
* **목적**: 7-Phase Vibe 루프 실행, 3대 시나리오 테스트, 1턴 자체 보완 및 DB 물리적 검증.
* **실행 절차**:
  1. **논의된 사항 구현 (7-Phase Loop)**:
     - `LOOP_ANALYZE` (P1) ➔ `LOOP_DESIGN` (P2) ➔ `LOOP_EXECUTE` (P3) 순환.
     - 주요 마일스톤마다 `SAVEPOINT_CREATE` 스냅샷 생성.
     - AI API 호출 시 3계층 Proactive Fallback 체인(`Claude` ➔ `Codex` ➔ `Gemini`) 가동.
  2. **3대 시나리오 테스트 구현 & 리팩토링 (P4 / P5)**:
     - 필수 정상 시나리오 (Happy Path)
     - 예외 경계 시나리오 (Edge Bounds)
     - 오류 복구 시나리오 (Error Recovery / 429 Timeout)
     - 정적 품질 린트 통과 (`tsc --noEmit`, 0 Error).
  3. **1턴 추가 보완사항 자체 보완**: 발견된 잠재 결함 및 예외 케이스 1턴 자체 리팩토링.
  4. **테이블 변경 및 데이터 마이그레이션 물리적 적용 확인 (P6)**:
     - DDL 실행 후 6대 감사 컬럼 주입 확인.
     - 테이블 코멘트(버전) 스탬프 및 `schema_migrations` 메타 레코드 등록 확인.
     - 실제 데이터 SELECT 쿼리로 물리적 적용 결과 검증.
* **게이트 체크리스트**:
  - [ ] 논의된 핵심 기능 구현 완료
  - [ ] 3대 시나리오 테스트 통과
  - [ ] 1턴 추가 보완 리팩토링 완료
  - [ ] DB 물리적 변경 및 메타 테이블 등록 검증 완료
  - [ ] 정적 린트 및 번들 빌드 0 Error

---

### 4️⃣ `#태스크정리` (Task Wrap-Up)
* **목적**: PR 생성(문서+원격), dev 머지, 작업자 소스 리뷰 및 승급 프롬프트 준비.
* **실행 절차**:
  1. **구현내용 PR 생성 (문서 + 원격 레포지토리)**:
     - 로컬 문서: `/docs/pull_requests/{번호}-{태스크명}.md` 생성 (제목/내용 템플릿 준용).
     - 원격 레포: GitHub 저장소에 `task/*` ➔ `dev` 대상 PR 등록 및 연결 이슈(#) 링크.
  2. **원격 dev 브랜치 머지**: 작업 브랜치 소스를 원격 `dev` 브랜치에 안전하게 병합.
  3. **원격 저장소 소스 리뷰 (작업자)**: 변경 내역 최종 셀프 검토, 빌드 산출물 무결성 확인.
  4. **태스크승급 프롬프트 작성**: 상위 환경 승급을 위한 `#태스크승급` 프롬프트 출력.
* **게이트 체크리스트**:
  - [ ] 로컬 PR 문서 작성 및 원격 레포 PR 등록 완료
  - [ ] 원격 `dev` 브랜치 머지 완료
  - [ ] 작업자 셀프 소스 리뷰 완료
  - [ ] `#태스크승급` 프롬프트 작성 완료

---

### 5️⃣ `#태스크승급` (Task Promotion)
* **목적**: dev ➔ stg ➔ main 다단계 승급, 미구현/보완사항 정리, 태스크 DB 정리 및 차기 액션 안내.
* **실행 절차**:
  1. **다단계 승급 처리**: `dev` 배포 소스를 `stg` 및 `main` 브랜치로 순차 승급 배포 (버전 태깅).
  2. **처리된 작업, 미구현 기능 및 보완사항 정리**: 작업 완료 내역 결산 및 파생된 백로그 항목 정리.
  3. **태스크 정보 정리 (DB)**: `task_nodes.status = 'DONE'` 갱신, `phase_gate_logs` 점수 기록 (여러 태스크 연속 처리 시 배치 누적 갱신).
  4. **작업목록 및 다음 프롬프트 표시**:
     - 세션시작 시 검토한 작업 및 태스크 진행과정에서 정리한 작업 목록 현황 표시.
     - 잔여 작업이 남은 경우 ➔ **다음 작업 `#태스크시작` 프롬프트** 표시.
     - 목록의 모든 작업이 종료된 경우 ➔ **`#세션정리` 프롬프트** 자동 표시.
* **게이트 체크리스트**:
  - [ ] `dev` ➔ `stg` ➔ `main` 다단계 배포 및 승급 완료
  - [ ] 미구현 기능 및 보완사항 백로그 정리 완료
  - [ ] PostgreSQL `task_nodes` DB 정리 완료
  - [ ] 차기 `#태스크시작` 또는 `#세션정리` 프롬프트 표시 완료

---

### 6️⃣ `#세션정리` (Session Wrap-Up & Retrospective)
* **목적**: 세션 결산, 세션명 한글 현행화, 회고록 작성, 원격 승급, 이슈 종료, DAG/DB 정리 및 차기 인계.
* **실행 절차**:
  1. **작업내용 정리 & 문서 현행화**: 세션 내 수행한 모든 작업 내역, 아키텍처 다이어그램, 백로그 문서 현행화.
  2. **세션명 현행화 (한글 세션명)**: 실제 완수된 성과를 정확히 반영하여 세션명 최종 갱신 (예: `[세션] PostgreSQL 스키마 개별/그룹/전체 현행화 및 6대 하네스 라이프사이클 표준 완결`).
  3. **회고 문서 작성**: `/docs/report/{순번}-{날짜}-세션종료-회고-보고서.md` 작성.
  4. **문서 및 배포누락 소스 승급**: 회고 문서 및 잔여 산출물 PR 작성 ➔ `dev` 배포 ➔ `stg`, `main` 최종 승급.
  5. **이슈 현행화 및 종료**: 세션 관련 원격/로컬 이슈 전체 `CLOSED` 처리.
  6. **작업그래프(DAG) & 세션 DB 정리**: 차기 후속 의존 노드 잠금 해제(`PLANNED`), `harness_sessions.status = 'COMPLETED'` 기록.
  7. **다음 세션 인계 프롬프트 작성**: 차기 세션에서 바로 이어받을 수 있는 완벽한 컨텍스트 브리프 출력.
* **게이트 체크리스트**:
  - [ ] 세션명 한글 최종 현행화 완료
  - [ ] 세션 종료 회고 보고서 작성 완료
  - [ ] 문서/누락소스 원격 dev 배포 및 stg/main 승급 완료
  - [ ] 원격/로컬 이슈 종료(`CLOSED`) 완료
  - [ ] PostgreSQL `harness_sessions` DB 정리 완료
  - [ ] 다음 세션 인계 프롬프트 작성 완료
